## Complexity derivations — cold, pre-review

### LC#1 Two Sum

**User derivation:**
- Time: O(n) outer loop + O(1) hashmap lookup per iteration → O(n). Conclusion correct.
- Space: Hashmap O(n) + result vector O(n) → O(n). Conclusion correct but attribution wrong.

**Corrections:**
- "Inner iteration through hashmap" — wrong phrasing. `map.find()` is a single O(1) lookup, not a traversal. No inner iteration.
- Result vector holds exactly two integers regardless of input size → O(1), not O(n). Hashmap alone drives the O(n) space.

### LC#49 Group Anagrams

**User derivation:**
- Time: n iterations + O(k log k) sort per string + O(1) lookup → "resolves to O(n)." Conclusion wrong.
- Space: Hashmap O(n) + result vector O(1) → O(n). Conclusion partially wrong.

**Corrections:**
- Dropped the k log k factor after correctly deriving it. Same mistake as W2 D2. Time is **O(n · k log k)** — the sort term does not disappear.
- Result vector holds all n grouped strings → O(n) at minimum, not O(1).

### LC#128 Longest Consecutive Sequence

**User derivation:**
- Time: O(n) outer loop + while loop O(1) per step, k steps per chain. Described per-chain cost but did not close the amortized argument.
- Space: Hashset O(n) + result O(1) → O(n). Correct.

**Probing exchange:**
- Q: "What prevents the while loop from running k steps for every element?" → "Only starter elements trigger it." Correct direction but conclusion still loose.
- Q: "How many times is any single element x visited by a while loop?" → "At max once." Correct.

**Closed argument:** Each element is visited by a while loop at most once — it belongs to exactly one chain, and only that chain's start triggers the count. Total inner steps across all chains ≤ n. **Time: O(n) overall.** Same shape as the "each element pushed and popped at most once" argument in W5 monotonic stacks.

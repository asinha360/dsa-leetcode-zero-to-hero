### LC#1 Two Sum [E]

**Pre-code statement:** Hash map. O(n) time (one pass, O(1) lookup). O(n) space (map stores at most n elements). Correct.

**Bugs encountered and resolved:**

1. `return result.insert(result.end(), {nums[i], key})` — `result.insert()` returns an iterator, not a vector. Fixed: insert first, then return.
2. Returned `nums[i]` (value) instead of `i` (index). Fixed after diagnostic question: "what does the problem ask you to return?"
3. `key` used as if it were an int — it is a `map::iterator`. Fixed after: "what does `map.find()` return?" → `key->second` to access stored index.
4. `return 0` fallthrough — int ≠ vector<int>. Fixed to `return result`.
5. Signed/unsigned comparison `i < nums.size()` — carry-forward from W1. Fixed to `static_cast<int>(nums.size())`.

**Verdict:** Accepted (63/63). Runtime beats 100% C++.

**Complexity verified:** O(n) time, O(n) space. Derivation matches implementation.

### LC#49 Group Anagrams [M]

**Pre-code statement:** "Hash sets, O(n) time, O(n) space." Both wrong — needed two redirects before code.

Redirects:
- Hash set vs hash map: "does a set map a key to a group of values?" → Corrected to hash map.
- Key structure: "what do two anagrams have in common if you sort them?" → User arrived at sorted string as key without scaffolding.
- Value structure: "indices or strings?" → User: strings. Correct.

**Bugs encountered and resolved:**

1. `x.sort(x.begin(), x.end())` — `std::string` has no `.sort()` method. std::sort is a free function.
2. `x` is `const string&` — can't sort in place. Needed mutable copy `x_cpy`.
3. `std::sort sorted_x = x_cpy.sort(...)` — `std::sort` returns void, not a string. Can't assign it.
4. Multiple iterations back to `x.sort()` before arriving at correct two-line pattern:
   ```cpp
   std::string x_cpy = x;
   std::sort(x_cpy.begin(), x_cpy.end());
   ```
5. Variable name mismatch (`sorted_x` vs `x_cpy`) after rename — fixed.

**Verdict:** Accepted (128/128). 14ms, beats 73.89% C++.

**Complexity correction:** User pre-coded O(n) time. Actual: O(n * k log k) — sorting each of n strings costs O(k log k) per string. User derived this correctly after being asked "what does std::sort cost on a string of length k?"

**Space complexity:** O(n * k) — all strings stored in map.

## 4b. Problems attempted

### LC#704 — Binary Search [E]

**Pattern identified:** Binary search (exact match on sorted array). Identified after deriving monotonicity from the YTM bisection analogy — pattern name was self-evident once the connection was made.

**Target complexity:** O(log n) — stated correctly before coding.

**Approach:** Built from first principles. Key steps derived via questions (not told): (1) bond price decreases as yield increases → monotonicity; (2) monotonicity is why half the interval can be eliminated at each step; (3) loop invariant: "if target exists, it is in [l, r]"; (4) `l <= r` checks the single-element case, `l < r` misses it; (5) `l = mid+1` / `r = mid-1` required — if `l = mid`, loop stalls on a 2-element array.

**Hints given:** None on algorithm. Direction questions only (Socratic).

**LeetCode verdict:** Accepted, 47/47 test cases, 0ms, beats 100% C++ runtime.

**Final complexity:** O(log n) time — "each step halves the search space; n / 2^k = 1 gives k = log n steps, each O(1)." User-derived after confirmation prompt. O(1) space — three fixed variables; user-derived.

**Code quality notes:** Clean first submission. `static_cast<int>(nums.size() - 1)` present without prompting — first time carry-forward appeared correctly on first attempt. Overflow-safe mid `l + (r - l)/2` applied correctly from derivation.

## 4c. Conceptual wins

- **Monotonicity as the basis for binary search** — after being asked "why can you throw away half the interval?", traced it to: bond price is strictly decreasing in yield → monotone → safe to eliminate. `[FIRST TIME in binary search context]`
- **Loop invariant stated correctly** — "the target is within the mathematical range l ≤ t ≤ r." Complete, in own words, no prompting beyond the framing question.
- **`l <= r` vs `l < r` correctly resolved** — traced the single-element [3,9] example with target 9: `l < r` exits at l==r without checking index 2; `l <= r` catches it. Got it right after the trace (initial answer had them swapped verbally but self-corrected immediately after the trace).
- **`l = mid+1` required for termination** — "l = mid doesn't advance the pointer, same state forever — infinite loop." Self-stated after being asked to trace the 2-element failure case.
- **W3 P1 spaced retrieval (s[l] over-shrink)** — score 2. "The window invariant is that the set always mirrors the window exactly — so s[l] is in the set by definition; contains(s[l]) is always true while window is non-empty, so the loop only stops when set is empty, past the duplicates." Complete causal chain, cold, no scaffolding. Confirmed durable across one-week gap.

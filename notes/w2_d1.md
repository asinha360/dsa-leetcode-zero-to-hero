## Concepts introduced

**Why hash map beats brute force:**
- Two Sum brute force: for each element, scan the rest for the complement → O(n) inner scan × n elements = O(n²).
- The inner scan asks one question repeatedly: "does this value exist?"
- A hash map answers that in O(1) via a hash function (key → array index).
- Result: n × O(1) = O(n) time, O(n) space.

**Key / value semantics:**
- Key = what you're looking up (the complement).
- Value = what the problem asks you to return (the index).
- Storing just existence isn't enough when the answer requires position.

**Hash set vs hash map:**
- Hash set: existence only ("is X in the set?"). No stored value. O(1).
- Hash map: key → value ("is X in the set, and what does it map to?"). O(1).
- LC#128 Longest Consecutive Sequence → hash set (only need existence; no value to return per lookup).

**PMF analogy:**
- A hash map is like a PMF over a discrete sample space: P(X = x) tells you instantly whether x is in the support and what weight it carries. No scan — evaluate a function.

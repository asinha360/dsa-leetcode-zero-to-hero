## 4b. Problems attempted

### LC#121 — Best Time to Buy and Sell Stock [E]

**Pattern identified:** "Variable sliding window" — sliding window is correct; "variable" is imprecise but accepted without correction.

**Complexity stated before coding:**
- Time: O(n\*k) — WRONG. No k in this problem. Corrected with one redirect ("how many times does each pointer visit each element?"). User responded "once so O(n)."
- Space: O(1) — correct.

**Approach taken:**
User went straight to sliding window; no brute force attempted. Started with nested while loops (outer loop condition: `r < prices.size() - 1`, inner while: advance l when price drops). The D1 carry-forward (l=r, not l++) was applied correctly and unprompted on first attempt.

**Bugs found and fixed, in order:**

1. `r` never advances in outer loop when `prices[r] >= prices[l]` → infinite loop.
   - Found: Claude asked user to trace [7,1,5]. User identified "r stays at 2 forever" after prompt.

2. No profit computation anywhere. `max` initialized but never updated.
   - Found: User self-identified after tracing.

3. `return max` inside both if/else branches → `r++` unreachable, loop exits after one iteration.
   - Found: User identified after prompt "which line does control flow reach after if/else?"

4. `max = prices[r] - prices[l]` overwrites running max instead of comparing.
   - Fix given directly: `std::max(max, prices[r] - prices[l])`. User did not know std::max.

5. `else { max = 0; }` resets running max to zero.
   - User self-identified: "else should not be there — max should be 4."

6. Outer loop condition `r < prices.size() - 1` off-by-one — misses last element.
   - Found: Claude asked user to trace [1,2]. User identified loop never starts.

7. Inner while loop has no bounds check → runtime error on [5,4,3,2,1] (r reaches prices.size()).
   - User identified "index out of bounds" after trace prompt. Fix given directly: prepend `r < prices.size() &&`.

8. User asked "do we need inner and outer loop at all?" → refactored to single if/else.
   - User correctly derived both branches: `if prices[r] < prices[l]: l = r` / else: `max = std::max(...)`.

9–11. In single-loop attempts: wrote `max = r` (index), then `max = prices[r]` (sell price only), then `max = std::max(max, prices[r])` (missing buy). Each caught and redirected. User dropped `prices[l]` three times across three consecutive attempts.

**LeetCode verdict:** Final single-loop solution reached and appears correct. "submitted successfully" stated mid-session (likely for an earlier buggy version). No explicit Accepted confirmation for the final version. **CARRY-FORWARD: confirm LC#121 Accepted at W3 D3 open.**

**Final complexity:**
- Time: O(n). Each element visited once by r. User-derived with one redirect (corrected from O(n\*k)).
- Space: O(1). User-derived correctly.

**Code quality notes:**
- Persistent issue: repeatedly dropped `prices[l]` from profit expression across three iterations.
- `int max` shadows `std::max` — minor, not flagged.
- Signed/unsigned comparison (`int r` vs `size_t`) — not flagged, deferred.

### LC#3 — Longest Substring Without Repeating Characters [M]

**Pattern identified:** Variable sliding window — correct.

**Complexity stated before coding:**
- Time: O(n) — correct.
- Space: O(k) / O(min(n, alphabet size)) — correct.

**Pre-code algorithm (user-stated), with corrections before coding:**
1. "l++" on duplicate → corrected to while loop. Condition given after "don't know": `while (set.contains(s[r])) { set.erase(s[l]); l++; }`.
2. "max_length + 1" → corrected to `std::max(max_length, r - l + 1)`. Given after "don't know."

**Bugs fixed during coding session:**

1. `set.emplace(s[r])` only inside duplicate branch → s[r] never added in the normal (non-duplicate) case.
   - User identified after prompt "what happens to s[r] when the if is skipped?"

2. Inner while loop: `l++` without `set.erase(s[l])` → duplicate never evicted, infinite loop.
   - User identified after prompt.

3. Inner while condition `set.contains(s[l])` instead of `set.contains(s[r])`.
   - User guessed "s[r]?" after prompt. Correct. (Checking s[l] would over-shrink: keeps moving until the current left char is absent, not until the specific duplicate is gone.)

4. `std::unordered_set` missing template type `<char>`.
   - User identified after prompt.

5. Missing `return max_length`.
   - User identified.

**LeetCode verdict:**
- Hashset version: Accepted, 988/988 (21 ms, 20th percentile).
- Hashmap optimization (char → index, `l = std::max(l, map[s[r]] + 1)`): Accepted, 988/988 (4 ms, 73rd percentile, 11.7 MB / 66th percentile).

**Optimization (hashmap):**
User asked if solution could be optimized. Claude directed to `unordered_map<char, int>` approach. Key line given after "show me": `l = std::max(l, map[s[r]] + 1)`. The `std::max` is required because l must not move backwards if the prior occurrence of s[r] is already behind l. User implemented and submitted. (Why the max matters was not probed — carry-forward.)

**Final complexity:**
- Time: O(n). Derivation: "each character is added and removed at most once" — user-stated correctly without scaffolding. `[FIRST TIME]`
- Space: O(min(n, alphabet size)) — user-derived correctly.
